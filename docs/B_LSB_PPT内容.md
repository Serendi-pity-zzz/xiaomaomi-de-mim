## 幻灯片正文（16:9，单页）

**标题：** CAT1 基础 LSB：PNG 保存后恢复 UTF-8 秘密

**一句目标：** 在不改二维码功能区的约定 RGB 区域嵌入秘密文本，并保证同一 PNG 可按密钥完整提取。

**三步原理：**

1. UTF-8 消息组成 CAT1 + 4 字节长度 + 32 字节消息 HMAC + 消息字节。
2. 依次取右侧 160×200 区域的 RGB 最低位；有密钥时先用 SHA-256 种子置乱位置。
3. 重开 PNG 后读头、取消息、比对 HMAC，再返回 passed / failed / unknown。

**建议主图：** 左侧画封包（4 B | 4 B | 32 B | ≤11960 B），右侧画「RGB LSB → PNG → 读头/校验/解码」。标注 160×200×3=96000 位、头 40 B、净容量 11960 B；标注图片区域与 A 的 CAT1 固定区域一致。此图是协议计算，不是效果实测；效果数据用下方结果表，不用示意图代替。

**真实结果小表（2026-11-09 本机实测，Python 3.13.14 / Pillow 13.0.0 / qrcode 8.2 / pyzbar 0.1.9）：**

| 检查 | 实测结果 |
|---|---|
| 全套 Python 回归（原有 2 + B 10 + 兼容 3） | 15/15 通过，约 2 s |
| 与原 baseline 像素逐字节比较（2 密钥 × 3 文本） | 6/6 一致；PNG 重存后双向交叉提取 6/6 恢复 |
| PNG 重存恢复（空、中文 emoji、11960 字节上限 × 2 密钥） | 6/6 恢复 UTF-8 原文 |
| 真实二维码载体双链路（2 种密钥） | 扫码 2/2、秘密恢复 2/2、二维码区域 2/2 逐字节不变 |
| 合成 PNG 样例 | 10 字节秘密重开后 passed；重新生成 SHA-256 一致 |

原始记录：`outputs/b_qr_carrier_results.json`；复现命令见 `docs/B_LSB_算法说明.md` 第 4 节。

**一句结论：** 固定 CAT1 规则下，B 能跨 PNG 保存恢复秘密、与原基线像素兼容，且嵌入不改动二维码区域、公开文本仍可解码。

**一句局限：** 置乱不等于加密；HMAC 仅覆盖秘密消息，不能证明整幅图未被改动。本页扫码是 MVP 并置载体的程序解码，不是 A 的艺术融合图或手机扫码，不替代 A 的正式验收。

## 讲述备注（约 40–60 秒）

原始图由 A 的二维码模块或现有基线提供，B 只接收 Pillow 图像并在固定猫咪条带写最低位。CAT1 把文本先转 UTF-8，所以容量要按字节而不是汉字数算。空密钥按 y、x、RGB 顺序；有密钥按原基线的 Python Random 规则置乱，提取端只需同一张图和同一密钥，不依赖未保存的元数据。消息位被改会让 HMAC 校验失败，错误密钥或无标记时则是 unknown，不能直接说图像遭到恶意篡改。本轮除了合成载体，还用现有二维码并置载体做了扫码和秘密恢复两条链路的实测，两种密钥模式都通过，二维码区域逐字节没变；但那是 MVP 图、程序解码，不是 A 的艺术融合图或手机扫码，A 交付后要重测。
