# D 答辩讲稿

## 1. 篡改检测与完整性校验

我负责D部分。现有项目能校验秘密消息，但图像高位和其他区域的变化不一定影响消息。我的工作是在最终含密图上建立受认证的像素分块记录，再进行三状态验证。

## 2. 从 mimi 现有实现出发

实际使用mimi的generate、embed、extract和positions。当前CAT1在右侧160乘200区域的RGB最低位写入消息，40字节包头后净容量11960字节。现有消息HMAC不覆盖高位，因此需要D的区域认证。

## 3. 认证记录如何生成

对每块计算带坐标的SHA256，再对包含尺寸、区域、标识和全部摘要的规范化JSON计算HMAC。验证时先认证记录，再逐块核对像素。验证端必须根据可信业务ID选取记录，不能只相信上传图随附的记录。

## 4. 三种状态与定位边界

通过表示声明区域的像素与受认证记录一致；失败表示在可信记录前提下发现像素或尺寸不符；未知表示没有足够可信基础。两处修改定位为两个失败块，红框不是逐像素定位。

## 5. 真实项目验收结果

自动回归包括原项目测试、D单元测试、CLI、真实service联调和原app的HTTP请求。38条实验均符合预期状态，图中的三类数量是预设功能条件造成的分布，不是分类准确率。

## 6. 最能说明问题的三个实测

第一，修改消息像素的高位后，秘密仍恢复、扫码仍成功，但D失败。第二，局部范围外改动通过局部认证，同样的改动在整图认证下失败。第三，抹除二维码但保留右侧猫咪，消息可恢复、局部D通过而扫码失败。这说明每种校验只能证明自己的覆盖对象。

## 7. 局限与组长交接

局部区域外和PNG文件字节没有被认证；HMAC依赖非空高熵密钥与可信记录映射，不防持钥者伪造，也不自动阻止旧记录重放。本次没有新增HTTP认证路由或改前端；由组长完成可信存储和页面适配。资料可按README复跑。
