# D 与 mimi 的真实接口交接

## 生产模块与适配入口

`core/tamper_detector.py`：`create_metadata(image, key, region=None, block_size=32, *, image_id=None)`、`verify(image, metadata, key)`。
`core/service.py`：`authenticate_image(...)`、`check_image_integrity(image, metadata, key)`；原 generate/embed/extract/detect 保持现有行为。

```python
from core import service

# integrity_key 由服务端安全输入/密钥管理提供；建议与stego_key分开。
cover = service.generate(public)
final_image = service.embed(cover, secret, stego_key)
region = (final_image.width - 180, 32, 160, 200)  # 当前mimi真实CAT1约定
record = service.authenticate_image(final_image, integrity_key, region, image_id=expected_id)
# 业务层：可信存储将 expected_id 与 record 关联保存。
# 收到待检图后，先按预期expected_id读取对应record，再调用：
result = service.check_image_integrity(uploaded_rgb_image, record, integrity_key)
```

不传region为整图认证。本次真实样例尺寸 `[528, 328]`，局部区域 `[348, 32, 160, 200]`，32px分块，实际 35 块。
region=(x,y,width,height)，绝对坐标，右下边界不包含。RGB三通道所有8位都参与摘要，包括区域内未写入消息的位置。
认证须在最后一次像素编辑后生成，不改变图像、不写入CAT1载体、不占用11960字节消息容量。

## 算法与元数据

版本 CAT-INTEGRITY-1，算法标识 HMAC-SHA256+SHA256-BLOCKS。每个块以域分离前缀+四个大端uint32坐标+按行RGB字节计算SHA256。
对含版本、算法、image_id、尺寸、区域、块大小和全部块摘要的manifest，用排序键、紧凑分隔、UTF8编码、禁用NaN的JSON序列化，再加域分离前缀计算HMAC-SHA256。
因此块摘要、覆盖范围和坐标均受同一个HMAC保护。元数据认证通过后才展示块状态；不是将未认证的哈希或RGB差值当作认证定位。
v1的规范化规则为Python json实现约定，未宣称符合通用JCS规范或已做跨语言互操作。

`metadata` 字段严格为 version、algorithm、image_id、image、region、block_size、blocks、tag，不含密钥和像素原文。
附带JSON可序列化并JSON往返；MAC用compare_digest核对。输入仅接受Pillow RGB，最大400万像素，块数最多16384，元数据限制400万字节。
CLI另外限定单帧RGB PNG，并拒绝JSON重复键；验证时不自动做颜色模式转换。

## 三状态语义与返回值

| status | 条件 | coverage与定位 |
|---|---|---|
| passed | 元数据认证通过，声明区域RGB像素全部匹配 | 受认证coverage、全部块passed |
| failed | 元数据已认证，但尺寸或覆盖内像素不符 | 尺寸变化不定位；像素不符给出失败块 |
| unknown | 缺/错密钥、记录缺失或无效、记录MAC不符、图像不可读等 | 不可信记录不输出coverage；记录可信而图片不可读时保留coverage，但不定位 |

`failed` 表明与可信记录不一致，不证明恶意行为或修改者身份；`unknown` 不计作passed或确认篡改。
主要字段：status、coverage、detail、reason、metadata_authenticated、localization_available、blocks；像素完成校验时还有failed_blocks、total_blocks。
coverage包含image_id、region、image_size、channels、bits_per_channel、pixel_bits、block_size、full_image、file_bytes_authenticated=false。
红框只表示整个认证块中至少存在不一致，不是逐像素精确定位。

## 可信基础及明确限制

1. 生成端必须可信，使用非空高熵完整性密钥，且只对最终图建立记录。空密钥不能建立图像认证。
2. 验证端须从可信业务上下文选择预期image_id及记录。仅上传一对匹配图像和记录不能阻止整对替换或旧版本重放；v1未提供抗回滚时间戳或版本存储。
3. 局部认证不覆盖区域外像素；整图认证覆盖全部RGB像素，但不认证PNG压缩方式、文本块、文件字节。
4. 不提供内容加密、签名不可抵赖、容错恢复或统计隐写检测。消息HMAC、扫码和D结果要分开展示。
5. 共享HMAC密钥持有者能生成记录；密钥泄漏会破坏认证假设。生产密钥持久化、轮换、权限与记录关联由组长实现。
