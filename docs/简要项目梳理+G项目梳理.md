# 小猫咪的秘密

项目要做的是一种**把秘密信息藏进猫咪图片里的二维码**的方法。

使用者会先得到一张普通二维码，里面可以放公开内容，例如网址；同时，系统把另一段秘密信息藏进猫咪图片的像素中，生成一张看起来仍像普通猫咪图片的 PNG。

整体目标是：

1. **公开信息能被普通二维码扫描器读取。**
2. **秘密信息藏在猫咪图片里，知道密钥的人才能提取。**
3. **提取后能检查秘密信息是否完整、正确。**
4. **通过实验评估图片质量、容量和受到压缩、裁剪等影响时的表现。**



## 前置知识

### LSB

LSB 是 **Least Significant Bit** 的缩写，中文叫“最低有效位”。一张 RGB 彩色图片里的每个像素由红、绿、蓝三个数值组成，每个数值通常在 **0 到 255** 之间。

也就是一像素一颜色转换成8位2进制后的最后一位

如果一张 RGB 图片有 \(W*H\) 个像素，并且每个像素的 R、G、B 三个通道都各用 1 个最低位，那么总容量是：

W*H*3

换算成字节，要再除以 8：

WH3/8

### **密钥置乱**

根据密钥生成一组确定的像素位置顺序，并按照该顺序将秘密数据的二进制位写入图片；提取时使用相同密钥生成相同的位置顺序，从图片中依次读取数据。它用于打乱秘密数据在图片中的存放位置，密钥置乱本身不等同于加密。

作用：打乱秘密数据在图片中的嵌入位置，减少按固定像素顺序直接读出数据的可能；只有使用相同密钥生成相同位置顺序，才能正确提取。密钥置乱负责位置安排，本身不负责加密内容。



## 步骤

### 一. 确定要传递的内容

**定义：** 使用者准备两段信息：一段是可以公开读取的内容，另一段是希望隐藏起来的秘密内容。

**作用：** 区分两种信息的用途。公开内容可以放进二维码，让普通扫码器读取；秘密内容留给后续步骤嵌入猫咪图片，再由知道密钥的人提取。



### 二. 生成公开二维码

**定义：** 将第一步准备的公开内容编码成二维码图案。二维码中的黑白模块代表编码后的数据，普通扫码器可以读取它。

**作用：** 让公开内容能被普通手机或扫码器直接识别。它只承载公开信息，不负责隐藏秘密内容。



#### (1) 二维码生成程序:

**定义：** 二维码生成是把输入文字编码为 QR Code 数据，并绘制成可扫描的黑白模块图像的过程。

**作用：** 让手机或扫码器通过识别图案，恢复出原始文字。



项目用 `qrcode` 库生成二维码，具体步骤是：

后端接收公开文字，用 `qrcode` 库将它编码成二维码图案，再把二维码图案粘贴到白色画布左侧，并在右侧绘制猫咪图案。

```pyhon
qr = qrcode.QRCode(
    error_correction=qrcode.constants.ERROR_CORRECT_H,
    box_size=8,
    border=4
)
qr.add_data(public)
qr.make(fit=True)
code = qr.make_image().convert('RGB')
```

输入是变量 `public`，也就是公开文字。例如：

```
public = "https://example.com"
```

`qr.add_data(public)` 把文字交给库，`qr.make(fit=True)` 让库根据内容选择合适的二维码尺寸，`make_image()` 生成二维码图像。

这段核心代码的输出是变量 `code`，它是一张二维码图像,   后面的代码把它贴到白色画布左边，并在右边画猫咪图案，最终由程序返回完整图片。

#####  QR Code 数据

**定义：** QR Code 数据是二维码图案所编码的内容。比如公开文字 `https://example.com`，编码后会成为一串数据，再经过二维码规则处理，变成扫码器能识别的黑白方格。

**作用：** 让扫码器从二维码图案中还原出原始文字或其他内容。

**例子：**

在 QR Code 的内部编码中：

- 字母数字模式的标识位是 `0010`
- 数据长度字段表示有 2 个字符：`0000000010`
- `H` 对应数字 17，`I` 对应数字 18。两个字符按公式 `45 × 17 + 18` 合并为 783，即 `01100001111`

因此这一部分的编码位串是：

```
0010 0000000010 01100001111
模式  字符数      字符数据
```

接下来还会加上结束标记、补齐数据，并加入纠错码（让扫码器在二维码有部分污损时仍有机会还原内容），最终再排成二维码黑白模块。

### 三. 生成猫咪二维码图片

**定义：** 项目把生成好的二维码图像粘贴到白色画布左侧，再在右侧绘制猫咪图案，组成一张完整图片。

**作用：** 左侧二维码承载可公开扫描的信息；右侧猫咪区域用作后续LSB嵌入秘密信息的像素载体，同时避免猫咪遮挡二维码的定位图案和静区。

#### LSB嵌入

**定义：** LSB 嵌入是把秘密数据转换成二进制位，逐位写入图像颜色数值的最低位。项目中每个选中像素的 R、G、B 通道都可以提供一个最低位。

**作用：** 将秘密数据藏进图像像素中。由于每次颜色数值通常只变化 0 或 1，图像外观一般变化很小；提取时读取这些最低位，可重组成原数据。

### 四.  把秘密信息打包并嵌入猫咪区域

**定义：** 项目先把秘密文本按 UTF-8 转成字节，再加上用于识别消息、记录长度和验证内容的数据，组成一个数据包；之后把数据包的二进制位用 LSB 写入右侧猫咪区域。若选择随机 LSB，密钥还会决定像素位置顺序。

**作用：** 数据包让提取程序知道“这里有一条消息、要读多长”，并能检查恢复内容是否正确；LSB 则负责把数据实际藏进猫咪图片。

**项目中的数据包格式：**

```
标记 CAT1（4 字节） + 长度（4 字节） + HMAC 校验值（32 字节） + 秘密文本（UTF-8 字节）
```

因此，嵌入的不只是秘密文本本身，还包括额外的数据。空密钥时，校验不具备可靠的密钥保护能力；随机 LSB 使用密钥置乱位置，但这本身也不等于加密。



##### 数据包

**定义：** 数据包是程序给秘密文本加上的固定格式信息，包含消息标记、文本字节长度、校验值和文本内容。

**作用：** 让提取程序能识别消息、知道要读取多少字节，并检查取回的内容是否与嵌入时一致。

以秘密文本 `HI`、密钥 `abc` 为例，生成过程如下：

1. **把文本转成 UTF-8 字节**

    ```
    "HI" → 48 49（十六进制）
    ```

    代码：`data = secret.encode('utf-8')`

2. **生成消息标记 `CAT1`**

    这是代码里写死的 4 个字节，用来识别本项目的数据包。它不是由 `HI` 计算出来的。

3. **记录文本字节长度**

    `HI` 的 UTF-8 长度是 2，程序把数字 `2` 存成 4 字节整数：

    ```
    00 00 00 02
    ```

4. **计算 HMAC 校验值**

    程序把密钥和 `HI` 的字节交给 HMAC-SHA-256，得到 32 字节校验值。这个值由内容和密钥共同计算出来；示例未展开其具体十六进制结果。

5. **拼接成数据包**

    ```
    CAT1 | 00 00 00 02 | HMAC 校验值（32 字节） | 48 49
    ```

提取时，程序先读出 `CAT1` 判断格式，再读长度字段，按长度取回内容，最后用同一密钥重新计算 HMAC 并比对。匹配则校验通过。

##### 举例：

以项目当前实现为准，数据包不是调用某种“自动打包”库生成的，而是 `core/baseline.py` 的 `embed()` 函数按固定格式**逐段拼接**出来的。

核心代码是：

```
data = secret.encode('utf-8')
packet = (
    b'CAT1'
    + struct.pack('>I', len(data))
    + hmac.new(key.encode(), data, 'sha256').digest()
    + data
)
```

例如输入秘密文本 `HI`、密钥 `abc`：

1. `secret.encode('utf-8')` 把 `HI` 转成两个字节：`48 49`（十六进制）。
2. `b'CAT1'` 是程序写死的 4 个标记字节，用来识别数据包格式。
3. `struct.pack('>I', len(data))` 把字节长度 `2` 转成 4 字节大端整数：`00 00 00 02`。
4. `hmac.new(...).digest()` 用密钥 `abc` 和内容字节 `48 49` 计算出 32 字节 HMAC-SHA-256 校验值。
5. `+` 把这些字节按顺序连接起来。

所以数据包的底层结构就是：

```
43 41 54 31 | 00 00 00 02 | 32 字节 HMAC | 48 49
   "CAT1"       长度字段        校验字段       "HI"
```

实际嵌入图片时，程序再把数据包中的每个字节拆成 8 个二进制位，逐位写进选定像素颜色数值的最低位。

### 五. 把图片保存成 PNG	

**定义：** 完成秘密信息嵌入后，程序把处理后的猫咪二维码图像保存为 PNG 文件。

**作用：** PNG 使用无损压缩，保存和重新打开时能保留像素数值。LSB 的秘密信息放在像素最低位，如果保存时像素被改动，后续提取就可能失败。

**项目中的流程：** 后端生成二维码与猫咪图片，按选定算法嵌入数据，再将最终图像编码成 PNG 返回，供用户预览或下载。接收方之后需要使用这份 PNG 进行提取。

### 六. 从 PNG 中提取秘密信息

**定义：** 提取是读取猫咪区域中用于 LSB 嵌入的像素最低位，并按嵌入时的规则重新组合成数据包，再恢复秘密文本的过程。

**作用：** 让接收者取回隐藏信息。若使用了密钥置乱，提取时必须使用相同密钥，才能按相同位置顺序读取。

**项目中的流程：**

1. 上传含密猫咪二维码 PNG，并选择嵌入时使用的算法。
2. 如果嵌入时使用密钥，输入同一个密钥。
3. 程序按对应位置顺序读取 LSB，先检查消息标记，再根据长度字段读取完整数据包。
4. 用相同密钥重新计算 HMAC 并比对；通过后按 UTF-8 解码并显示秘密文本。



### 七. 验证秘密信息是否正确恢复

**定义：** 提取后，程序用数据包中的 HMAC 校验值检查恢复出的秘密内容，再尝试按 UTF-8 解码。

**作用：** 确认取回的内容与嵌入时的内容一致，并发现密钥错误、数据损坏或读取位置不匹配等问题。

**项目中的判断：**

- HMAC 匹配且文本能正常解码：报告消息校验通过，并显示秘密文本。
- HMAC 不匹配：报告校验失败。
- 找不到 `CAT1` 标记：报告无法判断，可能是密钥不对、图片受损，或图片根本没有嵌入消息。

这项校验针对的是**秘密消息**，不代表整张图片都没有被修改。接下来项目会分别检查公开二维码能否扫描，以及图片处理会怎样影响二维码和秘密信息。



### 八. 分别检查二维码和秘密信息

**定义：** 项目把两种信息的验证分开进行：用普通扫码器读取左侧二维码，用提取程序和密钥读取猫咪区域里的秘密消息。

**作用：** 判断两条信息各自是否可用。二维码扫描成功，只能说明公开信息能读；秘密提取成功，才说明隐藏消息能恢复，二者不能互相替代。

**项目中的做法：**

- 用手机或二维码解码器扫描 PNG，核对读出的公开内容是否正确。
- 上传同一 PNG，使用正确算法和密钥提取秘密信息，核对内容及校验状态。

项目界面提示需要人工扫码确认；不能仅凭“PNG 已生成”就断定二维码已验证。



### 九. 测试图片受干扰后的表现

**定义：** 对生成的猫咪二维码施加 JPEG 压缩、噪声、遮挡、裁剪或旋转等处理，再分别检查二维码能否扫描、秘密信息能否提取。

**作用：** 观察图像变化对两种信息的影响。二维码带有纠错机制，可能在部分图像受损后仍可扫描；LSB 需要像素最低位保持一致，秘密提取通常更容易受到压缩或变形影响。

**项目中的结果记录：** F 任务的实验脚本会记录攻击类型和强度，并分别统计扫码与秘密恢复结果。测试结论只适用于记录的图像、参数和解码方法。



##### 项目中的干扰处理方式

**定义：** 实验程序读取含密图片，在内存中按指定类型和强度修改像素，然后生成一张受干扰图片。

**作用：** 模拟图片在保存或传递中可能遇到的变化，再检查二维码还能否扫描、秘密信息还能否提取。

项目默认用 `0、20、40、60、80、100` 六档强度；`0` 表示不做处理，用作对照。支持以下七种干扰：

1. **JPEG 压缩**：将图片编码为 JPEG，再解码回 RGB。强度 20 时，JPEG 质量约为 81；强度 100 时，质量为 5。
2. **高斯噪声**：给 RGB 各颜色通道随机加噪声。噪声标准差为“40 × 强度比例”；强度 100 时标准差为 40。
3. **椒盐噪声**：随机将像素改成纯黑或纯白。强度 100 时，约有 30% 的像素被选中。
4. **中心遮挡**：在图片正中央盖一个白色矩形，强度越高，矩形越大。
5. **定点遮挡**：在秘密数据所在区域盖白块，专门观察载荷被遮挡后对秘密提取的影响。
6. **四周裁剪**：从图片四边裁掉一部分，强度 100 时每边裁掉 20%，不补回原尺寸。
7. **旋转**：最多旋转 45°，保持原画布尺寸，旋转后空出来的区域填白。

处理完成后，实验会分别检查二维码解码结果和秘密提取结果。二维码扫描成功不代表秘密信息也能恢复；两项结果分别记录。



##### 强度和质量定义

**强度**是实验设定的干扰等级，范围是 0 到 100。它不是 JPEG 标准里的参数，而是项目用来控制“干扰做多重”的刻度：

- **强度 0**：不施加干扰，作为对照。
- **强度 20**：轻度干扰。
- **强度 100**：这一项测试设定中的最高强度。

对于 JPEG 测试，程序会把实验强度换算成 JPEG 编码器使用的**质量参数**：

\[ 质量 = 100 \times (1 - 0.95 \times 强度比例) \]

所以：

- 强度 20：比例是 0.2，质量约为 \(100 × (1 - 0.95 × 0.2)=81\)。
- 强度 100：比例是 1，质量为 \(100 × (1 - 0.95)=5\)。

**JPEG 质量参数**控制压缩程度。质量参数越高，通常压缩越轻、图像保留得越好；参数越低，压缩越重，图像损失越明显。因此强度 100 对应质量 5，是这项实验里的重度 JPEG 压缩。



### 十. 统计并比较实验结果

**定义：** 项目把不同干扰下的二维码扫描结果和秘密提取结果分别记录，再按干扰类型、强度和样本汇总成功率。

**作用：** 看出哪些变化会影响公开二维码、哪些会破坏秘密数据，并比较不同嵌入方法的表现。

例如，一张受干扰图片可能出现：

```
二维码扫描：成功，读出原公开网址
秘密信息提取：失败，LSB 校验未通过
```

这说明二维码的纠错机制恢复了公开内容，但像素变化破坏了秘密信息。项目会分别报告两种结果，不能把“二维码能扫出来”当成“秘密也成功恢复”。



### 十一. 比较不同的嵌入方法

**定义：** 项目把同一张载体图和同一份秘密数据交给不同嵌入方法处理，再比较图片质量、可嵌入容量、提取成功情况以及受干扰后的表现。

**作用：** 判断不同方法各自的特点，了解它们在视觉变化、数据容量和提取可靠性之间的取舍。

项目里会比较 B 任务的顺序 LSB、密钥置乱 LSB，以及 G 任务的密钥置乱和自适应嵌入方法。比较时需要使用相同载体、相同秘密内容和相同实验条件，结果才有可比性。



### 十二. G 任务的自适应嵌入如何接入项目

**定义：** G 任务把密钥置乱、Sobel 边缘分档和局部方差分档等方法，接入统一的嵌入与提取流程，让实验能用同一载体和同一秘密内容比较这些方法。

**作用：** 让 G 的方法能和 B 的顺序 LSB、密钥置乱 LSB 在一致条件下对比，并验证嵌入端和提取端是否能生成相同的位置顺序。

**项目中的流程：**

1. 适配器准备二维码载体、猫咪区域和可用像素范围。
2. G 根据载体、区域、遮罩和密钥计算位置顺序。
3. G 将消息封包后写入这些位置的 LSB，并保存为 PNG。
4. 提取端用同样的输入条件重新计算位置顺序，读取消息并验证校验值。
5. 实验对照其他算法，记录提取、图像质量和抗干扰结果。

**需要注意：** 这是 G 算法与实验的接入流程；仓库说明当前演示基线与 G 实验适配载体并不完全相同，讨论实验结果时要说明使用的是哪种载体。



### 十三. G 任务的实验评估

**定义：** 实验评估是在相同载体、秘密内容和参数条件下，运行不同嵌入方法，记录每种方法的嵌入耗时、提取结果、图像质量和受干扰后的表现。

**作用：** 判断 G 的位置选择方法是否按预期工作，以及它和顺序 LSB、密钥置乱 LSB 相比有什么差异。

**项目主要检查：**

- 秘密数据能否正确提取、校验是否通过。
- 嵌入前后图像变化有多大，例如 PSNR、SSIM。
- 不同算法的嵌入与提取耗时。
- 经过 JPEG、噪声、裁剪、旋转、遮挡后，二维码扫描和秘密提取是否成功。
- 写入前后计算出的位置顺序是否一致，受保护的二维码区域是否保持不变。

**结果怎么理解：** 实验数值只适用于所用载体、样本、载荷和参数。二维码扫描、秘密提取和消息完整性校验是不同指标，不能用其中一项代替其他项。



## 不同嵌入方法（五种）

项目实验中主要比较这五种嵌入方法：

1. **B-sequential（顺序 LSB）**：按固定像素顺序，把秘密数据逐位写入最低位。
2. **B-keyed（密钥置乱 LSB）**：用密钥打乱像素位置，再逐位写入；提取时需使用相同密钥。
3. **G-keyed（密钥置乱的自适应 LSB）**：G 方法根据密钥确定位置顺序，并结合图像特征选择嵌入位置。
4. **G-sobel（Sobel 边缘自适应）**：根据 Sobel 算出的边缘强度安排嵌入位置，倾向选择边缘更明显的区域。
5. **G-variance（局部方差自适应）**：根据局部纹理变化程度安排位置，倾向选择纹理更复杂的区域。





### 方法一：B-sequential（顺序 LSB）

**定义：** 顺序 LSB 是按固定顺序选择图像中的颜色通道，把秘密数据的二进制位逐位写进这些通道的最低位。项目会先打包秘密信息，再从载体区域的第一个可用位置开始写入。

**作用：** 用简单直接的方式把秘密信息藏进图片，便于实现和作为其他嵌入方法的比较基准。

**怎么写入：**

假设秘密数据的下一位是 `1`，选中位置的颜色数值是 `156`：

```
156 = 10011100（二进制，最低位是 0）
```

程序把最低位改成 `1`：

```
157 = 10011101（二进制，最低位是 1）
```

如果原最低位已经等于要写入的位，就不必修改。这样逐位写下去，直到整个数据包写完。

**“顺序”具体指什么：** 项目先规定载体区域里的像素顺序，再按每个像素的 R、G、B 通道顺序遍历。例如：从上到下逐行扫描，每行从左到右；每个像素依次处理红、绿、蓝通道。提取时按相同顺序读取最低位。

**特点：**

- 不需要密钥就能按固定位置读写。
- 实现简单，适合作为基准方法。
- 数据位置有规律，隐藏位置的保护较弱。
- 图片一旦经过压缩、裁剪或旋转，像素值或顺序可能变化，秘密信息容易提取失败。



### 方法二：B-keyed（密钥置乱 LSB）

**定义：** B-keyed 是先用密钥打乱图像载体区域内可写入的位置，再像顺序 LSB 一样，把秘密数据包的二进制位逐位写入颜色数值的最低位。

**项目中怎么打乱位置：**

1. 把密钥转成 UTF-8 字节。

2. 对密钥计算 SHA-256，得到一个固定摘要。

3. 用摘要生成随机数种子。

4. 用这个种子打乱载体区域内所有候选位置。

    **底层例子：**

    底层分两步：**把密钥摘要变成整数种子**，再用这个种子初始化一个伪随机数生成器。项目里的实现可以简化写成：

    ```
    digest = hashlib.sha256(key_bytes).digest()
    seed = int.from_bytes(digest, "big")
    rng = random.Random(seed)
    rng.shuffle(positions)
    ```

    具体来说：

    1. `hashlib.sha256(key_bytes).digest()` 对密钥字节计算 SHA-256，得到固定的 32 字节摘要。
    2. `int.from_bytes(digest, "big")` 把这 32 个字节按大端顺序解释成一个大整数，作为种子。
    3. `random.Random(seed)` 用这个种子初始化 Python 的伪随机数生成器。
    4. `rng.shuffle(positions)` 根据生成的一系列伪随机数，把位置列表原地打乱。

    相同种子会让这个伪随机数生成器从相同的内部状态开始，因此在同一套实现中会产生相同的随机数序列，`shuffle` 也就得到相同的位置顺序。换密钥通常会得到不同的摘要、种子和顺序。

    **项目中的真实代码**就是先对密钥做 SHA-256、转成整数种子，再调用 `random.Random(seed).shuffle(result)`。这个方法用于产生可复现的置乱顺序；它不是秘密内容加密。

项目的载体区域是猫咪图像右侧规定的 `160 × 200` 像素区域，每个像素的 R、G、B 通道各提供一个位置。于是秘密位会分散写入这些位置，而不是从第一行开始连续写。

**提取时怎么读：** 接收者输入相同密钥，程序重新生成相同的位置顺序，再按顺序读取最低位，重组数据包并校验内容。

**作用：** 让秘密数据的位置顺序不再固定，增加直接按像素扫描读出数据的难度。

**特点：**

- 密钥错误时，程序会按错误位置读取，通常无法找到有效的 `CAT1` 标记或无法通过 HMAC 校验。

- 相同密钥会产生相同置乱顺序，因此才能正常提取。

- 置乱改变的是数据存放位置，不会加密秘密文本本身。

    

    ##### shuffle打乱

    项目调用的是 Python 的 `random.Random(seed).shuffle(positions)`。它会从列表末尾往前走，每次选一个当前位置之前（含当前位置）的随机下标，然后交换这两个位置上的元素。

    例如列表是：

    ```
    [A, B, C, D]
    ```

    假设这次生成的随机下标依次是 `j=1、j=0、j=0`：

    1. 从末尾下标 `i=3` 开始，交换 `positions[3]` 和 `positions[1]`：

        ```
        [A, D, C, B]
        ```

    2. `i=2`，交换 `positions[2]` 和 `positions[0]`：

        ```
        [C, D, A, B]
        ```

    3. `i=1`，交换 `positions[1]` 和 `positions[0]`：

        ```
        [D, C, A, B]
        ```

    最后得到的新顺序就是置乱后的写入顺序。真实项目里，列表有很多像素通道位置；同一密钥产生相同的伪随机下标，所以嵌入和提取会得到相同顺序。

    上面的随机下标只是演示用的假设值，不是项目运行时对特定密钥实际生成的序列。

    

### 方法三：G-keyed（G 的密钥置乱方法）

**定义：** G-keyed 根据密钥和载体图像生成一个确定的位置顺序，再按这个顺序把秘密数据位写进载体区域的 LSB。使用同一张载体和同一密钥，嵌入方与提取方会得到相同的位置顺序。

**它和 B-keyed 的区别：** B-keyed 先按固定规则列出位置，再用密钥打乱列表；G-keyed 则用密钥对每个位置计算排序值，再按排序值排列位置。这样，位置顺序由密钥和图像区域信息共同决定。

**项目中怎么生成顺序：**

1. 列出允许写入的像素通道位置。
2. 将密钥、位置坐标及算法用途标识组合起来计算 HMAC-SHA-256 排序值。
3. 按排序值从小到大排列位置。
4. 按排列后的顺序写入或读取秘密数据位。

**作用：** 让秘密数据位置依赖密钥，同时使位置顺序可重复生成，不必把整张置乱列表保存在图片里。

**特点：** 它仍然是位置置乱加 LSB 嵌入，不会加密秘密文本。G-keyed 是 G 的基础方法；后两个 G 方法会再用图像纹理特征来调整嵌入位置



**具体步骤：**

1. 列出允许写入的候选位置。一个位置包含像素坐标和颜色通道，例如 `(x, y, R)`。
2. 把密钥、该位置的坐标和通道编号，以及用途标记组合起来。
3. 对组合数据计算 HMAC-SHA-256，得到一个固定长度的摘要。
4. 把每个位置对应的摘要作为排序键，从小到大排序。
5. 按排序后的顺序逐位写入秘密数据。

举个简化例子，假设候选位置只有 A、B、C：

```
位置 A → 摘要排序值 8F…
位置 B → 摘要排序值 21…
位置 C → 摘要排序值 C4…
```

按摘要从小到大排列后，顺序为：

```
B → A → C
```

实际项目的摘要是完整的 SHA-256 长度；这里仅用 `8F…` 等做示意。提取时用同一密钥、同一图像上下文和同一位置列表重新计算排序值，就会得到相同顺序。相比 B-keyed 的“先列出位置再整体 shuffle”，G-keyed 是“为每个位置计算排序值再排序”。

### 方法四：G-sobel（Sobel 边缘自适应）

**定义：** G-sobel 根据图像中每个像素附近的亮度变化，计算该处的边缘强度，再优先选择边缘较明显的位置嵌入秘密数据。

**怎么做：**

1. 将载体图像转换为灰度图。
2. 对灰度图应用 Sobel 算子，分别估计水平方向和垂直方向的亮度变化。
3. 合并两个方向的变化，得到每个像素的边缘强度分数。
4. 按边缘强度对候选位置分组或排序，并用密钥打乱相同等级里的位置。
5. 按排序结果逐位进行 LSB 嵌入。

简单理解，纯色、平滑区域的分数较低；轮廓、纹理边界处的分数较高。算法倾向把数据写在分数较高的位置，因为这些地方原本颜色变化更明显，微小的像素调整相对不容易被察觉。

**作用：** 利用图像本身的边缘特征安排嵌入位置，减少对平滑区域的修改。

**限制：** 这是位置选择策略，不会让 LSB 自动抵抗 JPEG 压缩、裁剪或旋转；图像处理仍可能破坏最低位。

#### G-sobel 具体怎样计算并安排写入位置？

在项目的 G 实现里，Sobel 分数是这样算的：

##### 1. 先把 RGB 变成灰度亮度

RGB 各通道先清除最低位，再按加权公式合成灰度值：

```
R' = R & 254
G' = G & 254
B' = B & 254

亮度 Y = (77R' + 150G' + 29B') >> 8
```

这里 `R、G、B` 是像素颜色值；`>> 8` 表示把结果右移 8 位，得到整数亮度。绿色权重较大，蓝色较小，因为人眼对不同颜色的亮度感受不同。

##### 2. 查看周围 3×3 像素的亮度变化

对每个像素，程序取它周围的 3×3 亮度值，使用 Sobel 模板计算横向、纵向变化：

```
横向模板 Gx：       纵向模板 Gy：

-1  0  1            -1 -2 -1
-2  0  2             0  0  0
-1  0  1             1  2  1
```

把模板中的数字分别乘以周围对应的亮度，再求和，得到 `Gx` 和 `Gy`。项目用：

```
边缘分数 = |Gx| + |Gy|
```

分数越大，代表周围亮度变化越明显，也就是越像边缘。

##### 3. 按分数从高到低分档

项目会把候选像素按 Sobel 分数**从高到低**排序，再分成 4 档。最高分档的像素属于边缘变化最明显的区域。不是简单地先把最高分像素全部写完，而是先按分数分档，再在每档内用密钥生成顺序。

##### 4. 在这些位置写秘密数据

程序根据“分档顺序 + 密钥顺序”排列 RGB 通道位置，然后依次把秘密数据包的二进制位写到这些通道的最低位。提取时重新计算亮度、Sobel 分数和位置顺序，再读取最低位。

**简单理解：** 先用每个像素周围的亮度差判断哪里是明显边缘，再优先把嵌入位置安排到高分边缘区域；同档位置的先后由密钥决定。

### 方法五：G-variance（局部方差自适应）

**定义：** G-variance 根据像素周围一小块区域内的亮度变化计算局部方差分数，再按分数把候选位置分档。项目倾向先把秘密数据写入局部变化较大的纹理区域。

**怎么计算：**

1. 先把 RGB 像素转换成整数亮度，计算方式与 G-sobel 相同。
2. 对每个像素取周围的 **3×3 亮度区域**。
3. 计算这 9 个亮度值的局部方差。方差越大，说明周围亮度差异越明显、纹理变化越丰富。
4. 按方差分数从高到低分成四档。
5. 每档内部再用密钥安排位置顺序，最后按顺序逐位写入 LSB。

**作用：** 让嵌入位置优先落在较复杂的纹理区域。纹理处本来就有较多亮暗变化，少量颜色改动通常更不显眼。

**与 G-sobel 的区别：** G-sobel 主要衡量方向性边缘变化；G-variance 衡量周围亮度整体分散程度。两种方法都用亮度特征分档，再在档内按密钥排序。

#### G-variance 的具体计算和写入顺序

##### 1. 把 RGB 转成亮度

项目先清除每个颜色值的最低位，再计算整数亮度：

```
R' = R & 254
G' = G & 254
B' = B & 254

Y = (77R' + 150G' + 29B') >> 8
```

`Y` 是这个像素的灰度亮度值。`& 254` 清除最低位，是为了让嵌入前后用于算纹理的图像保持一致。

##### 2. 取每个像素周围的 3×3 区域

对一个像素，取它自身和周围八个像素的亮度值，记作 \(Y_1,\dots,Y_9\)。

项目不使用浮点方差，而是计算：

```
分数 = 9 × (Y₁² + Y₂² + … + Y₉²)
       − (Y₁ + Y₂ + … + Y₉)²
```

这等于 **9 × 这九个亮度值的方差**，乘以 9 不会改变大小排序。

- 九个亮度很接近：分数小，区域比较平滑。
- 九个亮度差异大：分数大，区域纹理变化较明显。

##### 3. 排序并分成四档

程序把可用像素按分数**从高到低**排序；分数相同的像素按坐标 `y`、再按 `x` 排序。然后根据排名分成四档：

```
第 0 档：纹理分数最高
第 1 档：次高
第 2 档：再次
第 3 档：分数最低
```

**重要：** 不是把所有位置严格按分数从高到低逐个写完，而是先分四档。正文先用第 0 档，再用第 1、2、3 档；每一档内部再按密钥计算的位置顺序排列。

##### 4. 按排列结果写入

每个位置包含坐标和颜色通道，例如 `(x, y, R)`。确定顺序后，程序把数据包的二进制位逐个写入对应通道的最低位。

**简单总结：**

```
RGB → 亮度 → 3×3 局部方差分数
→ 分数由高到低排序 → 分四档
→ 高分档优先、每档内密钥排序 → 写入 LSB
```

提取时会重新计算同样的亮度、分数、分档和密钥顺序，才能在相同位置读回数据。
